# 课表 App 设计文档

日期：2026-09-15
状态：待评审

---

## 1. 背景与目标

把教务处导出的 PDF 课程表，一键导入成手机上一张能用的课表。

现状是：PDF 只能看不能用 —— 想查「今天第几周、上什么课、去哪上」得自己在一张大表里找。本 App 解决这件事。

**使用者**：作者本人 + 几个朋友，各自装各自的 App、各自导自己的 PDF。**不上架应用商店**。

**成功标准**：打开 App 第一眼就知道今天上什么课、几点、在哪；想查某周的安排滑一下就够。

---

## 2. 范围

### 做

- 导入本校教务系统导出的课程表 PDF（Apache PDFBox 本地解析，不联网）
- 「今天」页：当天课程时间轴
- 「课表」页：整周网格，可左右滑动切换周次
- **课表页就地编辑**（核心交互，见 §7.2）：
  - 点**有课**的格子 → 弹窗列出候选课，可编辑 / 删除
  - 点**空白**格子 → 弹窗新增课程（星期与节次自动预填）
  - 点**左侧时间栏**某一节 → 弹窗修改该节起止时间
- 「其他课程」：PDF 第 3 页底部那个区块（无固定上课时间），课表页右上角按钮进入查看
- 设置：学期名称、开学日期、学期总周数
- 本地存储（无账号、无服务器、无云同步）

### 不做

- **不上架任何应用商店** —— 无需软著、App 备案、商店审核；包名不锁定
- 不支持其他学校的课表模板（见 §6.3 扩展性）
- **不保留 PDF 中 5 个字段以外的信息**（教学班、教学班组成、考核方式、学时、学分等一律丢弃，见 §5）
- 「其他课程」不参与课表网格、不参与「今天」页、不参与周次推算（它没有固定时间），只在一处列表里查看
- 不做云同步、账号体系、社交分享
- 不做导出/备份（已确认：只存本地）

## 3. 数据来源：课程表 PDF 的结构

样本：`李明轩(2026-2027-1)课表.pdf`，6 KB / 3 页。已完成完整逆向，**20 门网格课程 + 15 个字段全部还原，字符级审计零丢失**。

| 属性 | 值 |
|---|---|
| 生成器 | iText 5.5.10（Java） |
| 嵌入图片 | 0 张 —— 表格全部是矢量线条 |
| 字体 | `STSong-Light-UniGB-UCS2-H`，**未嵌入字体文件** |
| 页面 | A4 横版 + `/Rotate 90` |
| 文字层 | **有，中文抽取无乱码 —— 不需要 OCR** |

### 3.1 版面几何（实测）

- 星期列文字起始 x：`[104.1, 207.9, 311.8, 415.6, 519.5, 623.4, 727.2]`（列边界 + 5pt），7 列等宽各 103.85pt
- 行 = 节次 1~11，**行高不均匀**（152.5 / 67.8 / 31.3 三种，因合并单元格而变）
- 时间段分组：上午（1-4 节）、下午（5-8 节）、晚上（9-11 节），「时间段」列垂直合并

### 3.2 课程正文格式（高度规整，可直接反解）

```
课程名★
(1-2节)1-7周/场地:2-3-305/教师:赵鹏/教学班:机械设计基础-0012/教学班组成:智能科学与技术2501;…/考核方式:考查/选课备注:/课程学时组成:理论:28,实验:4/周学时:4/总学时:28/学分:2
```

类型符号图例：★理论 ☆实验 ◆上机 ■实践 〇课外

### 3.3 必须在解析中处理的复杂情形（均实测出现）

1. **单双周交替**：周一 5-6 节 = 大学英语(3)☆（1-15周**单**）+ 概率论与数理统计B★（2-16周**双**）
2. **同学期不同周段**：周五 1-2 节 = 国家安全教育（10-11周）+ 形势与政策（13-14周）。教务系统挤到相邻行显示，**导致「格子位置 → 时间」不是一对一映射**
3. **跨节次**：物理实验(2) 占 2-4 节；金工实习 占 5-8 节
4. **同一课程反复出现**：机械设计基础出现 3 次（理论/实验分排，教学班不同）
5. **课程名折行**：`毛泽东思想和中国特色社会主义理论体系概论★` 被拆成 4 行，`★` 可能单独占一行
6. **跨页截断**：正文断在页底、续在下一页顶部
7. **场地是自由文本**：`2-3-305` / `体育馆203柔力球` / `2-18-工程训练中心` / `2-物理实验2` / `未排地点`
8. **教师可为多人**：`黄远,徐雯`、`罗华,谢天成,韩雷,白鸿飞`
9. **学分精度不一**：`2` 与 `2.0` 并存，另有 `0.25`
10. **课程名全角/半角括号混用**：`大学英语(3)` vs `国家安全教育（3）`
11. **学时组成含「课外」**：图例未列该类型

## 4. 技术选型

| 项目 | 选择 | 理由 |
|---|---|---|
| 语言 | Kotlin | 安卓官方首选 |
| 界面 | Jetpack Compose | 课表是高度自定义的网格，Compose 比 XML 布局代码量显著更少 |
| PDF 解析 | PDFBox-Android | 纯 Java、Apache 2.0、本地运行。**不用系统 `PdfRenderer`**：其文字抽取 API 是 API 35 才加入，与最低版本冲突 |
| 存储 | 单个 JSON 文件 | 数据量仅 20 门课 + 10 条作息。JSON 可直接打开排查问题。Room 需建表与迁移机制，对本规模属于过度设计 |
| 最低版本 | Android 8.0（API 26） | 覆盖面广，PDFBox 支持 |

**文件访问**：使用 SAF（`ACTION_OPEN_DOCUMENT`）让用户选 PDF。不申请 `MANAGE_EXTERNAL_STORAGE` —— 这是 Android 系统层面的限制，与是否上架无关。

## 5. 数据模型

```
Timetable                        整份课表（全 App 仅一份）
├─ 学期名            String      "2026-2027 第1学期"
├─ 开学第一周周一      LocalDate   2026-08-31
├─ 总周数            Int         16
├─ 作息时间          List<PeriodTime>
├─ 课程列表          List<Course>
└─ 其他课程列表       List<OtherCourse>

PeriodTime                       作息时间，每节一条
├─ 节次编号          Int         1 … 11
├─ 开始 / 结束       LocalTime   可为空（见 §5.3）
└─ （渲染时按 节次编号 排序）

Course                           课程（只保留 5 组字段）
├─ 课程名称          String      含类型符号，如 "大学英语(3)☆"
│                                 （见 §5.4 为什么符号并入名称）
├─ 起始周 / 结束周     Int         课程周期
├─ 周类型            Enum        每周 / 单周 / 双周
├─ 星期              Int         1 = 周一 … 7 = 周日
├─ 开始节 / 结束节     Int         1 … 11
├─ 教室地点          String      自由文本，不拆结构
└─ 任课老师          String      可能含逗号分隔的多人
```

```
OtherCourse                      其他课程（无固定上课时间，不参与网格）
├─ 课程名称          String      含类型符号，如 "电路基础实验☆"
├─ 起始周 / 结束周     Int         可为同一个值（如「19周」）
├─ 总周数            Int?        PDF 里的「共 N 周」
├─ 教室地点          String      样本中恒为「无」，存原值
└─ 任课老师          String
```

**为什么单独一个类型**：其他课程没有星期与节次（课程节数这一维度对它们不存在），硬塞进 `Course` 会让「课程节数」变成可空字段，进而污染网格渲染与 `isActiveIn()` 判断。分开存，两条数据通路互不干扰。

### 5.1 周次必须存结构，不能存字符串

不存 `"2-16周(双)"`，而拆成 `起始周 / 结束周 / 周类型` 三个字段。原因：「今天上哪门课」每次都要判断某周是否生效，结构化后判断退化为一行逻辑：

```
course.isActiveIn(week) =
    起始周 ≤ week ≤ 结束周
    && (周类型 == 每周
        || (周类型 == 单周 && week 为奇数)
        || (周类型 == 双周 && week 为偶数))
```

**约定**：单周 = 学期第 1、3、5… 周（第 1 周视为单周）。样本中「概率论B 2-16周(双)」印证了该约定 —— 第 1 周为单周时，双周恰好从第 2 周开始。

### 5.2 当前周次的计算

```
当前周次 = floor((今天 − 开学第一周周一) / 7) + 1
```

样本验证：`2026-08-31` 为周一，`2026-09-15` 为其后第 15 天 → 第 3 周 ✓

### 5.3 节次 11 与缺失的作息条目

PDF 的网格有 11 行节次，但本校实际只用到 1–10 节（第 11 行在本样本中为空），默认作息时间也只提供 10 条。

若解析出第 11 节的课（或作息时间被用户删到只剩几条），则该课程：

- 在网格中**照常按节次行显示**，课程信息完整
- 时间栏显示「—」而非错误时间
- 编辑弹窗标黄提示「第 N 节还没有作息时间，点左侧时间栏补一下」

不允许因缺时间而丢弃课程。

### 5.4 课程名称包含类型符号

PDF 正文里的课程名带一个类型符号（★理论 ☆实验 ◆上机 ■实践 〇课外），如 `大学英语(3)★` 与 `大学英语(3)☆` 是两门不同的课。

已决定不为它单独设字段，而是**直接并进「课程名称」保存**。这样：

- 字段数量仍是 5 组，符合「只存 5 个」的决定
- 理论课与实验课在界面上仍可区分，不会看起来一模一样
- 显示时与原始 PDF 一致

### 5.5 「哪些字段不可信」要单独记一笔

上面 5 组字段之外，`Course` 还带一个 `missingFields: Set<CourseField>`，记录**导入时用了兜底值**的字段：

| CourseField | 何时记上 | 兜底值 |
|---|---|---|
| `NAME` | 课程名那一行没解析出来 | `"未知课程"` |
| `WEEKS` | 正文里没有 `N-M周` | 第 1–16 周、每周 |
| `PERIODS` | 正文里没有 `(N-M节)` | 第 1–1 节 |
| `LOCATION` | 正文里没有 `/场地:` | `""` |
| `TEACHER` | 正文里没有 `/教师:` | `""` |

**为什么必须记**：兜底值与用户手填的值长得一模一样（都是空串、都是 1），不单独记录，界面就无法区分「PDF 里本来就没有」和「用户故意留空」，§8 要求的「编辑弹窗标黄」也就无从判断。

它**不是** PDF 里的第 6 组数据 —— 不参与渲染、不参与周次计算，只驱动标黄提示。用户在任何一次编辑保存后，该课的标记整体清空（用户已经看过并确认了这些值）。

## 6. 解析流水线

```
1. SAF 选文件 → 取得 PDF 读取流
2. PDFBox 逐页读出「文字片段 + 坐标 + 字号」
3. 坐标变换：页面为 /Rotate 90，先转正
4. 按 x 坐标吸附到 7 个星期列（容差 6pt）→ 定「星期几」
5. 同列内按「页序 + y」排序后顺次拼接 → 解决跨页截断
6. 按字号切分课程名与正文，解析出 5 组字段
```

### 6.1 各复杂情形的落点

| 情形 | 处理 |
|---|---|
| 课程名折行 | 第 6 步：字号 ≥ 8.5 且**本课已有正文**才判定为新课程，否则并入当前课程名 |
| 跨页截断 | 第 5 步：溢出文字落在下一页顶部**同一列的相同 x 坐标**，故同列按页序拼接即可还原 |
| 同格多课 | **不做几何推断**。节次与周次直接从正文的 `(1-2节)`、`2-16周(双)` 标签解析；坐标只用于确定星期几 |
| 课程名没解析出来 | 课程名兜底为「未知课程」，其余字段照常保留，不因单个字段失手丢弃整门课 |
| 某字段缺失 | 该字段留空，并在编辑弹窗标黄提示 |

**只需要解析 5 组字段。** 按 §2 的取舍，解析器只提取以下内容，其余正则一律不写：

| 字段 | 来源 |
|---|---|
| 课程名称（含类型符号） | 课程名行，保留 `★☆◆■〇` 不剥离 |
| 课程周期 | 正文 `(\d+)-(\d+)周` 与可选的 `(单)` / `(双)` |
| 课程节数 | 正文 `\((\d+)-(\d+)节\)` ＋ 所属星期列 |
| 教室地点 | 正文 `/场地:(.*?)/` |
| 任课老师 | 正文 `/教师:(.*?)/` |

`/教学班:`、`/教学班组成:`、`/考核方式:`、`/课程学时组成:`、`/周学时:`、`/总学时:`、`/学分:`、`/选课备注:` 全部跳过。

**另外单独解析「其他课程」区块。** 它位于 PDF 第 3 页底部，格式与主表毫无关系：用 `;` 分隔条目、条目之间以三个空格缩进、整体换行。

```
其他课程：电路基础实验☆何建军(共16周)/1-16周/无;   电子产品设计■黄远,徐雯(共1周)/19周/无;   机械设计基础☆赵鹏(共3周)/2-4周/无;   …
```

单条格式为 `{课程名}{类型符号}{教师}(共N周)/{周次}/{场地}`，正则：

```
(.+?)([★☆◆■〇])(.+?)\(共(\d+)周\)/([^/]+)/([^;]*)
```

**注意周次既可能是区间也可能是单周**：`2-4周` / `1-16周` 是区间，而 `19周` / `18周` / `20周` 是单周（起始周 = 结束周）。

该区块必须先按行拼接（它本身跨了两行），再按 `;` 切分。

### 6.2 解析器接口

解析模块与 UI、存储完全解耦，对外只暴露：

```
parse(input: InputStream): ParseResult

ParseResult = Success(Header, List<Course>) | Failure(原因)
Header = { 学期名, 姓名, 学号, 打印时间, 校区 }   // 取自 PDF 页眉，字段可为空
```

页眉里的**学期名**会用来预填设置页的「学期名称」（如 `2026-2027 第1学期`），用户可改。姓名与学号仅用于让用户确认导入的是不是自己的课表，不做其他用途。

### 6.3 扩展性（3~5 所学校）

当前解析器只针对本校模板。**新增学校 = 新增一个独立解析器**，不改动现有解析器。因此解析层设计为可替换实现：根据 PDF 的生成器标识与表头特征选择对应解析器；匹配不到任何解析器时返回「这不是本 App 支持的课表格式」。

## 7. 界面设计

底部导航三个 Tab：**今天 / 课表 / 设置**

### 7.1 今天（默认 Tab）

全天时间轴。顶部显示今天日期与第几周，竖向按时间顺序列出当天的课。

- 已结束的课变灰，下一节高亮
- 当天无课 → 显示「今天没课」
- 学期未开始 / 已超出总周数 → 显示对应提示，不崩溃
- 点课程卡片 → 打开弹窗（同 §7.3）

### 7.2 课表

左侧为节次编号 + 起止时间，右侧 7 天网格。左右滑动切换周次（**左滑 = 下一周，右滑 = 上一周**，与顶部 ◀ ▶ 箭头一致）。滑动范围为**第 1 周至第 N 周**（N = 设置里的「学期总周数」，默认 16）；到达两端后继续滑动无效果，不循环。

卡片规则：

- 本周应上的课 → 彩色卡片，内容为「课程名 / @场地」
- 本周不上但该时段有课 → **灰色卡片 +「非本周」标记**（信息不丢失，视觉上区分）
- 该时段有多门候选课 → 右上角蓝色圈码标注数量

**本页是所有编辑动作的唯一入口。** 三种点击目标对应三种弹窗，全部原地弹出、不跳转页面：

| 点击目标 | 弹出 |
|---|---|
| 有课的格子 | 候选课弹窗（§7.3） |
| 空白的格子 | 新增课程弹窗（§7.5） |
| 左侧时间栏的某一节 | 修改作息时间弹窗（§7.4） |

顶部栏两个按钮：

- **导入课表**（参考图右上角 `+` 的位置）
- **其他课程**（小按钮，点开看 PDF 第 3 页底部那个区块，见 §7.6）

### 7.3 点有课的格子 → 候选课弹窗

- 标题显示「周一 · 第 5-6 节」与时间范围
- 列出该时段**全部候选课**，每门显示周次、教室、老师
- **本周实际生效的那门高亮**，其余置灰
- 每门课提供「编辑」与「删除」两个按钮
- 底部一个「＋ 在这个时段加一门课」入口（表单见 §7.5，节次预填为该时段）

**删除**：点击后弹二次确认「确定删掉这门课？」，确认后才删除。

边界：若同一周内该时段有多门课同时生效（数据本身冲突，例如用户手动加课时填重了），则**全部高亮，不做取舍**，由用户自己判断。App 不替用户决定上哪一门。

### 7.4 点左侧时间栏 → 修改作息时间弹窗

点网格左侧某一节的时间（如 `08:05 – 08:55`），弹窗内修改这一节的开始与结束时间。

弹窗内注明：**改这里影响所有用到第 N 节的课，不会改动课程本身。**

默认作息时间（学校实测）：

| 节次 | 起 | 止 |
|---|---|---|
| 1 | 08:05 | 08:55 |
| 2 | 09:00 | 09:50 |
| 3 | 10:05 | 10:55 |
| 4 | 11:00 | 11:50 |
| 5 | 14:10 | 15:00 |
| 6 | 15:05 | 15:55 |
| 7 | 16:05 | 16:55 |
| 8 | 17:00 | 17:50 |
| 9 | 19:00 | 19:50 |
| 10 | 19:55 | 20:45 |

### 7.5 新增 / 编辑课程弹窗

**新增与编辑共用同一个 5 字段表单**，区别只在标题和进入时的预填值。

| 字段 | 控件 | 新增时预填 | 编辑时预填 |
|---|---|---|---|
| 课程名称 | 文本框 | 空 | 原值 |
| 课程周期 | 第 X 周 到 第 Y 周 ＋ 每周 / 单周 / 双周 | 第 1 周 到 第 N 周，每周 | 原值 |
| 课程节数 | 星期下拉 ＋ 第 X 节 到 第 Y 节 | **所点格子的星期与节次** | 原值 |
| 教室地点 | 文本框 | 空 | 原值 |
| 任课老师 | 文本框 | 空 | 原值 |

**5 个字段全部可修改，没有任何一个是只读的。** 预填只是省事，不是锁定 —— 比如在周三第 5-6 节点空白新增后，照样可以把「课程节数」改成周四第 3-4 节。

两个入口：

- 点**空白**格子 → 新增，星期与节次预填为所点的那一格
- 点**有课**格子 → 候选课弹窗（§7.3）→ 选某门课的「编辑」，或点底部「＋ 在这个时段加一门课」

保存时的校验：

- 课程名称不能为空（没名字的课无法显示）
- 课程周期与节次必须合法：起始 ≤ 结束，节次 1–11，周次 1–总周数
- 教室地点与任课老师**允许留空**

导入来的其余信息已按 §2 丢弃，界面上不再出现。

### 7.6 其他课程

课表页顶部栏的「其他课程」小按钮点开后，列出 PDF 第 3 页底部那个区块的全部条目。

- 每条显示：课程名称（含 ★☆ 符号）、周次范围、共几周、任课老师
- 按周次排序
- **纯查看**：不参与课表网格、不参与「今天」页、不参与周次推算（它没有固定时间）
- 条目**不可编辑、不可删除**，保持与 PDF 一致

## 8. 错误处理

| 情况 | 行为 |
|---|---|
| 选的文件不是 PDF | 提示「这个文件读不了」，**不写入**，现有课表不变 |
| PDF 模板不匹配 | 提示「这份课表认不出来，可能是别的学校的模板」，**不写入** |
| 解析出 0 门课 | 同上，**不写入** |
| 个别字段未识别 | 照常导入，字段留空，编辑弹窗标黄 |
| 课程名未识别 | 兜底「未知课程」，其余字段保留 |
| 用户删除课程 | 弹二次确认；删除后不可撤销（无备份机制） |

### 8.1 关于导入覆盖

已确认：**导入不弹确认框，直接覆盖现有课表**。

但保留一条底线：**当解析结果为 0 门课时拒绝写入**。这不是确认弹窗，而是拒绝把空数据写进去抹掉用户的课表。这条同时覆盖「选错文件」「模板不匹配」两种误操作。

### 9.1 测试策略

解析器是唯一有实质逻辑且无 UI 的部分，**重点用单元测试覆盖**：

- 用样本 PDF 作为测试夹具，断言解析出 20 门课
- 逐个断言 4 类复杂情形：单双周交替、同格不同周段、跨节次、跨页截断
- 断言课程名折行合并（毛泽东思想…概论必须是 1 门而不是 4 门）

**测试夹具**：把样本 PDF 复制到 `app/src/test/resources/sample-timetable.pdf`，作为解析器的固定输入。该文件含姓名与学号，仅存于本地仓库，不外传。

UI 部分不写自动化测试，手动在模拟器与真机上验证。
